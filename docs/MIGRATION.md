# 迁移计划

| 阶段 | 工作 | 准入 |
| --- | --- | --- |
| A | 独立 WinUI 面板与点击诊断 | 用户完成点击/层级实测 |
| B | 稳定类型识别、去抖、重启发现 | 目标系统误判/漏判可解释 |
| C | 能力协商、受限 UI 与 IPC | SDK/宿主/管理器协同与兼容验证 |
| D | 插件逐个接入 | 多实例、并发、取消、崩溃验收 |
| E | 配置与布局迁移 | 中断、恢复、回退验证 |

本轮实现 A 的代码与非交互检查，用户交互验收仍待完成。B–E 尚未实现。

既有代码、其他 agent 改动、旧构建入口保留。迁移先备份有效配置，再写明确版本的新格式，失败不覆盖。桌面图标单位、负坐标不直接变成面板网格；用户确认后提交新排列。

插件/实例 ID、启停、插件配置与业务数据目录保持可追溯。缺失插件占位，重装后恢复。是否继续保留旧桌面入口，在新面板验证后决定。

优先确定不激活点击是否足够、WinUI 控件是否触发激活、普通置顶是否满足用户全屏场景、类型是否稳定。失败时采用“自动查看 + 手动完整交互”，不强制重开或注入 Shell。旧框架测试不代替新验收。
